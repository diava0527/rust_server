# 可持久化网络键值存储系统（kvstore）

> 《高级系统编程技术》课程设计 —— 基于 Rust 的可持久化网络键值存储系统的设计与实现

一个使用 Rust 编写的、支持**数据持久化**与**多客户端并发访问**的键值存储系统。
系统由 **服务器程序** 与 **命令行客户端** 两部分组成，用户通过客户端完成数据的
写入（set）、查询（get）、修改（覆盖写）、删除（del）、列出键（list）与状态查看（status）。

---

## 一、功能特性

| 模块 | 说明 |
|------|------|
| 命令模型与协议解析 | 基于「换行分隔 JSON」的文本协议，用 Rust 枚举表达命令，覆盖写入/查询/修改/删除/列键/状态 |
| 命令行客户端 | 交互式解析用户输入，连接服务器，发送请求并格式化显示结果 |
| 服务器程序 | 监听 TCP 连接，解析请求，调用存储模块并返回结果 |
| 运行时数据管理 | `HashMap` + `Mutex` 实现线程安全的内存态 |
| 数据保存与重启恢复 | JSON 快照落盘，启动时恢复；文件损坏时报错拒绝清空 |
| 多客户端访问 | 「每连接一个线程」模型，多客户端可同时读写 |

**启动与恢复行为**（对应验收要求）：

| 情况 | 系统行为 |
|------|----------|
| 首次启动 | 自动创建 `data/` 目录与数据文件，以空数据库运行 |
| 数据文件已存在 | 启动时读回内容，恢复已有数据 |
| 数据文件损坏 | 给出明确错误提示并退出，**绝不静默清空数据** |

## 二、系统架构

采用 Cargo 标准的「库 + 二进制」组织方式：可复用逻辑全部集中在 `src/` 下的库模块中，
`src/bin/` 下只保留很薄的启动入口，两个二进制共享同一个库。

```
客户端 (bin/client)                      服务器 (bin/server)
     │                                        │
     │  Request (NDJSON over TCP)             │
     └────────────────────────────────────────┤
                                              │
                               ┌──────────────┴───────────────┐
                               │ protocol   命令模型 + 消息读写 │
                               │ store      HashMap + Mutex    │
                               │ persistence JSON 快照落盘      │
                               └───────────────────────────────┘
```

**关键设计决策**：

- **协议**：换行分隔的 JSON（NDJSON）。TCP 是字节流、无消息边界，用换行符切分完整消息；
  JSON 可读性强，便于答辩演示与调试。
- **并发**：`Arc<Store>` 共享存储 + `Mutex` 保护数据 + 每连接一线程。
  存储读写很频繁，`Mutex` 的简单可预测优于 `RwLock`（避免过早优化）。
- **持久化**：写操作后「先写临时文件、再原子重命名」，避免写盘中途崩溃产生半截文件；
  用一把 `persist_lock` 串行化「快照 + 写盘」，防止并发写盘时临时文件冲突与丢失更新。

## 三、项目结构

```
kvstore/
├── Cargo.toml               # 包配置与依赖
├── README.md                # 本文档
├── .gitignore
├── src/
│   ├── lib.rs               # 库入口，声明模块

│   ├── persistence.rs       # JSON 快照持久化与重启恢复

│   └── bin/
│       ├── server.rs        # 服务器入口（clap 解析参数）
│       └── client.rs        # 客户端入口
└── tests/
    └── integration.rs       # 端到端 / 多客户端 / 重启恢复集成测试
```

## 四、快速开始

### 环境要求

- Rust 工具链（1.65+，建议最新稳定版），由 [rustup](https://rustup.rs) 安装
- 操作系统不限（本项目在 WSL Ubuntu 上开发验证）

### 编译与运行

```bash
# 1. 编译（首次会下载并编译依赖）
cargo build

# 2. 启动服务器（终端 1）
cargo run --bin server
# 默认监听 127.0.0.1:7878，数据存 data/kv.json
# 自定义参数：cargo run --bin server -- --addr 0.0.0.0:9000 --data-file data/kv.json

# 3. 启动客户端（终端 2）
cargo run --bin client
# 自定义服务器地址：cargo run --bin client -- --addr 127.0.0.1:9000

# 4. 运行测试
cargo test
```

## 六、通信协议

客户端与服务器之间传输换行分隔的 JSON 文本（NDJSON），每行一条完整消息。

**请求**（带标签枚举，`type` 为命令名，`payload` 为参数）：

```json
{"type":"set","payload":{"key":"课程名称","value":"Rust程序设计"}}
{"type":"get","payload":{"key":"课程名称"}}
{"type":"del","payload":{"key":"课程名称"}}
{"type":"list"}
{"type":"status"}
```

**响应**（`ok` 表示成功与否，失败时 `error` 给出提示）：

```json
{"ok":true,"value":"Rust程序设计"}
{"ok":false,"error":"键 \"课程名称\" 不存在"}
{"ok":true,"keys":["a","b"]}
```

## 七、演示流程（答辩脚本）

对应课设要求的现场演示，可按下述步骤进行：

1. **启动服务器** —— 打印监听地址、数据文件路径、已恢复的键值对数量
2. **启动客户端** —— 显示「已连接到服务器」
3. **写入**：`set 课程名称 Rust程序设计`
4. **查询**：`get 课程名称` → 返回 `Rust程序设计`
5. **修改**：`set 课程名称 Rust程序设计(第二版)` 再 `get` 验证覆盖
6. **删除**：`del 课程名称` 再 `get` 验证「键不存在」的明确提示
7. **查询不存在的数据**：`get 不存在的键` → 返回明确的错误提示
8. **多客户端**：再开一个客户端，两个同时操作均正常
9. **重启恢复**：`Ctrl+C` 关闭服务器，重新启动，`get 课程名称` 数据仍在
10. **异常处理**：输入 `foobar` 等非法命令、或直接关掉客户端，均给出提示、不崩溃

## 九、依赖清单

所有依赖由 Cargo 自动从 crates.io 下载，无需手动安装：

| 依赖 | 版本 | 用途 |
|------|------|------|
| `serde` | 1 | 序列化框架（`derive` 特性自动生成实现） |
| `serde_json` | 1 | JSON 序列化/反序列化（协议与持久化） |
| `thiserror` | 2 | 自定义错误类型的 `#[derive(Error)]` 宏 |
| `anyhow` | 1 | 二进制入口处的错误便捷包装 |
| `clap` | 4 | 命令行参数解析（`--addr`、`--data-file`） |

网络、并发、文件读写、CLI 交互均使用 Rust 标准库，无额外依赖。
